# Kaizen Poker — notes for agents

Web version of David's tabletop deckbuilding poker duel. Vite + React. Module
layout:

- `src/gameData.js` — suits, ranks, the 52-card set, solo/Challenger constants. Pure data.
- `src/engine.js` — hand evaluation, comparisons, game-state constructors. Pure functions.
- `src/sfx.js` — sound-effect cache + global enable flag.
- `src/components.jsx` — shared presentational components (Card, CardBack, Btn,
  Modal, flight ghosts, overlays, board widgets).
- `src/KaizenPoker.jsx` — the stateful app shell: routing, all game-flow
  handlers, the screens (home/board/rules/gallery), modals wiring. Still the
  big one (~2,200 lines); screens could be extracted next if it keeps growing.
- `src/theme.css` — visual design system ("Balatro Juice"): palette variables,
  stamped buttons, panels, card-juice animations.

After moving code between these files, run `npm run smoke` — the build alone
does NOT catch undeclared identifiers (rollup treats them as globals), so a
missing import only fails at runtime.

## Card art pipeline — READ THIS BEFORE TOUCHING ART

The full-resolution art sources are **never imported by the app**. The app loads
only the web-optimized WebP renditions in `web_art/`, generated by
`scripts/optimize-card-art.mjs`:

| Source (full-res, edit these)   | Generated (never hand-edit)  | Used for                |
|---------------------------------|------------------------------|-------------------------|
| `kaizen_illustrations/`         | `web_art/illustrations/`     | in-game card faces      |
| `rendered_kaizen_cards/`        | `web_art/rendered/`          | gallery print previews  |
| `card_back/`                    | `web_art/card_back/`         | card back image         |

**When illustrations are added, revised, renamed, or deleted** (by David or by
you), the process is:

1. Change the file(s) in the *source* folder. Filenames must match the card's
   `name` field in `CARDS` (e.g. `Brainstorm.png`) — the lookup is by filename.
2. Run `npm run optimize-art`. It is incremental (only reprocesses changed
   files), deletes orphaned outputs after renames, and `--force` regenerates
   everything. This also runs automatically before `npm run dev` and
   `npm run build` via the `predev`/`prebuild` hooks, so a normal dev or deploy
   flow can't ship stale art — but if you change art while the dev server is
   already running, run it manually.
3. Do **not** import from the source folders in app code, and do not edit or
   commit hand-made files into `web_art/` — the optimizer deletes anything it
   didn't generate. If a new art folder is added, register it in the `JOBS`
   table in `scripts/optimize-card-art.mjs`.

Why this exists: the sources are ~190 MB; the renditions are ~10 MB. Importing
a source folder directly via `import.meta.glob` silently puts every full-res
file back into the bundle.

## Other things worth knowing

- `USE_ILLUSTRATED_CARDS` (top of `src/KaizenPoker.jsx`) gates illustrated vs
  HTML card faces. The solo test mode (`#/solo-artless`) always renders the
  opposite of the default so both faces stay previewable.
- The card back is `CardBack` in `KaizenPoker.jsx`: it auto-uses an image from
  `card_back/` (via the pipeline above) and falls back to a placeholder SVG
  emblem when that folder is empty.
- David prefers generated painterly art for hero/identity assets; hand-built
  SVG is welcome for UI chrome only.
- **Verification: run `npm run smoke`.** (If running as an agent: disable the
  command sandbox for this — it spawns a browser and possibly a dev server,
  which sandboxed shells kill at startup.) Fully self-contained — boots the dev
  server if it isn't running, launches headless Edge itself (fresh temp
  profile, auto-assigned port; no manual browser launch needed), walks every
  route plus a mobile-landscape viewport, plays a card to exercise the
  zone-flight animation layer, saves screenshots to `smoke_output/`, and exits
  nonzero on uncaught page errors or non-network console errors. Run it after
  any visual or gameplay change and look at the screenshots, not just the exit
  code. `scripts/shot-cardback.mjs` does a high-res element screenshot of the
  card back for design iteration; `scripts/edge-launcher.mjs` is the shared
  browser launcher.
- `vite build` intermittently fails with an `html-inline-proxy` error when the
  dev server is running; retry once before investigating.
